## Overview

Java demos is a standalone CLI application that demonstrates and explains Java Enhancement Proposals (JEPs) from Java 11 through Java 27. Each JEP is implemented as a self-contained demo with inline explanations and Markdown Javadoc headers.

## Tech Stack

| Category       | Technology |
| -------------- | ---------- |
| Language       | Java 27 (OpenJDK 27, with `--enable-preview`, `--add-modules=jdk.incubator.vector`, and `--add-exports=java.base/jdk.internal.vm.annotation=ALL-UNNAMED`) |
| Build Tool     | Apache Maven (`pom.xml`, `maven-compiler-plugin` 3.16.0, `maven-shade-plugin` 3.6.2, `maven-clean-plugin` 3.5.0, `maven-javadoc-plugin` 3.12.0) |
| Dependencies   | Lombok 1.18.48 (`provided`), Gson 2.14.0 (`compile`), JOL `jol-core` 0.17 (JEP 519), ASM `asm` 9.10.1 (JEP 371) |
| Packaging      | Uber/shaded JAR (`target/JavaDemos-27.0.jar`) via `maven-shade-plugin` |
| CI/CD          | GitHub Actions (`.github/workflows/pr-build-check.yaml` builds on Oracle JDK 27 and executes the JAR to catch runtime exceptions) |
| Testing        | No unit test suite (`src/test/` is absent); verification runs `mvn clean install` and executes the shaded JAR |

## Architecture

The project is a single-module CLI monolith that loads JEP metadata from JSON resources and runs matching demo classes sequentially:

```text
Main.main(args)
  ├── ArgsFilterUtil.getFilteredJepData(args, JEPInfo.JEP_DATA)
  │     ├── Parses CLI filters (--skip-links, --code-only, --jdk, --only, --no-info, --output)
  │     └── OutputTee.install(path) -> duplicates stdout/stderr to demos-java.output (or custom path)
  ├── JEPInfo.JEP_DATA  <- loads src/main/resources/JDK{11..27}Info.json via Gson
  ├── JEPInfo.JEP_DEMO  <- invokes Java{11..27}DemoLoader.loadDemos(map)
  └── Filters, sorts by (jdk, jep), and runs each IDemo.demo()
```

## Key Directories

- `src/main/java/org/javademos/` - Application source root containing `Main.java` and per-JDK packages (`java11/` through `java27/`), each with per-JEP subpackages (`jep<NUM>/`).
- `src/main/java/org/javademos/commons/` - Shared core interfaces and utilities (`IDemo`, `IDemoLoader`, `ArgsFilterUtil`, `OutputTee`).
- `src/main/java/org/javademos/init/` - Metadata registry (`JEPInfo`) and per-JDK demo loaders (`Java11DemoLoader` through `Java27DemoLoader`).
- `src/main/resources/` - Per-JDK JSON metadata files (`JDK11Info.json` through `JDK27Info.json`) and auxiliary source files used by specific demos (`jep458/`, `jep512/`).
- `.github/workflows/` - GitHub Actions CI workflow (`pr-build-check.yaml`).
- `.agents/skills/` - Project-specific skills (`demo-create`, `demo-update`, `pr-create`, `article-add`) and AgentCreed skills.
- `tmp/` - Gitignored scratch directory for files generated by demos at runtime.

## Entry Points

- Main class: `org.javademos.Main` (`src/main/java/org/javademos/Main.java`)
- Metadata & demo registry: `org.javademos.init.JEPInfo` (`src/main/java/org/javademos/init/JEPInfo.java`)
- CLI filtering & output redirection: `org.javademos.commons.ArgsFilterUtil`, `org.javademos.commons.OutputTee`
- Shaded JAR artifact: `target/JavaDemos-27.0.jar`

## Conventions

- **Package layout**: Demos are organized under `org.javademos.java<N>.jep<NUM>`, with one `IDemo` implementation per JEP package. Older demos (JDK 22 and earlier) are still being migrated from legacy topic-based subpackages.
- **Demo contract**: Each demo implements `org.javademos.commons.IDemo` and begins `demo()` with `info(jepNumber)` to print the standardized header from `JEPInfo.JEP_DATA`.
- **Metadata and registration**: Every demo has a record in `src/main/resources/JDK<N>Info.json` with fields in the order `jep`, `jdk`, `name`, `dscr`, `link`, `code`, and is registered in `org.javademos.init.Java<N>DemoLoader`. Both JSON entries and loader registrations are ordered by ascending JEP number.
- **Preview and incubator chains**: Active code lives in the newest JEP iteration; earlier iterations are link-only stubs (`"link": true`, `"code": false`) pointing to the latest implementation.
- **Documentation comments**: Demo classes use Java 23+ Markdown Javadoc (`///`) headers containing JEP info, JEP history, further reading links, and `@author <git user.name> <<git user.email>>`. Inline comments explain behavior and reasoning.
- **Generated files**: Demos that create files write them under the gitignored `tmp/` directory.
- **Line endings**: Repository files use LF line endings (`.gitattributes`).
